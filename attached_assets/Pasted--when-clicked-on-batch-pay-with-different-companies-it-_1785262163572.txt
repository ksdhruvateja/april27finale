Here's everything that was built:

transactions table — permanent ledger

Every payment writes an immutable row containing:

Column	What it stores
txRef (computed)	TXN-00001, TXN-00002… — unique human reference
type	invoice_payment / bill_payment / walkin_sale_payment
source_ref	INV-0042, BILL-0007 — which document was settled
entity_name	Customer name (invoices) or Vendor name (bills)
amount	Final paid amount after any discounts
payment_method	cash / credit_card / bank_transfer / check / wire_transfer / ach
reference_number	Check # for checks, Dwolla transfer ID for ACH, Checkeeper ID for mailed checks
bank_account_id	Which bank account was used
note	Payment note from the user
paid_at	Exact UTC timestamp of when payment was recorded
Owe only reduces on full success — enforced atomically

Both pay routes now wrap everything in a single database transaction:

BEGIN
  UPDATE invoices/bills SET status='paid', paidAt=… WHERE id=?   ← owe reduction
  INSERT INTO transactions (type, amount, method, …)               ← ledger record
COMMIT  (only if both succeed)

If either write fails, the whole thing rolls back. The status stays unpaid, no ledger entry is created, and the caller gets a 500. This covers all paths — early-pay discount, Dwolla ACH, Checkeeper check, regular payments.

Auto-documented across all three payment surfaces

Invoices — every /invoices/:id/pay call writes a transaction (including early-pay discounts; the discounted final amount is what's recorded)
Walk-in / quick sales — these go through the same invoice pay route; they're recorded as walkin_sale_payment type so you can filter them separately
Bills — every /bills/:id/pay call writes a transaction, capturing the Dwolla/Checkeeper reference number if one was generated
